# ノートブック

ノートブックは、ユーザーごとのコンテナで動く JupyterLab を、Fione の「**ノートブック**」画面の中に開いたものです。ノートブックのコードは `fione-sdk` を通して、自分の権限でプロジェクトにアクセスできます。二度目のログインは要りません。ノートブックは既定では無効で、使うときに有効にします。Compose の構成にゲートウェイ、ランチャー、ノートブックのイメージが加わり、ランチャーは Docker ソケットを持ちます（[既知の制限](known-limitations.md#notebooks)、英語）。
English: [Notebooks](notebook.md).

## ノートブックを有効にする

`docker/.env` にノートブックの値を追加します（`docker/.env.example` も参照）。2 つの URL は、ブラウザで入力するアドレスと同じホスト名にし、ゲートウェイのポートだけ変えます。

```sh
printf 'FIONE_PUBLIC_URL=http://127.0.0.1:8080\nFIONE_NOTEBOOK_URL=http://127.0.0.1:8888\nFIONE_NOTEBOOK_LAUNCHER_SECRET=%s\n' "$(openssl rand -hex 32)" >> docker/.env
```

続けて、Compose のプロファイル `notebook` を付けてビルドし、起動します。

```sh
docker compose -f docker/compose.yaml --env-file docker/.env --profile notebook build
docker compose -f docker/compose.yaml --env-file docker/.env --profile notebook up -d
```

ビルドでノートブックのイメージ（約 950 MB。arm64 で 947 MB を測定）とランチャーができます。ランチャーはイメージを取得しないため、ノートブックのイメージがないまま起動すると「ノートブックのイメージがインストールされていません」と表示されます。`--profile notebook` を付けなければ、これまでどおりノートブックなしで動き、`FIONE_NOTEBOOK_URL` が空の間は「**ノートブック**」のリンクも出ません。`docker/.env` にノートブックの値を入れたら、以後の Compose のコマンド（`build`、`up`、`down`）にはすべて `--profile notebook` を付けてください。付けないと、Compose はノートブック用のサービスに手を付けず（更新してもそのイメージはビルドし直されません）、それらを起動しないままだとノートブックの画面に「現在、ノートブックのサービスを利用できません」と表示されます。

設定項目はすべて[設定](configuration.md)（英語）にあります。`docker/.env` では `FIONE_PUBLIC_URL`、`FIONE_NOTEBOOK_URL`、`FIONE_NOTEBOOK_LAUNCHER_SECRET`、`FIONE_NOTEBOOK_PORT`、`FIONE_NOTEBOOK_MAX_LIFETIME_SECS`、ランチャーでは `FIONE_NOTEBOOK_MAX_RUNNING` です。

## 構成

```
ブラウザ ──> Fione (:8080)                       ノートブック画面、API
ブラウザ ──> ゲートウェイ (:8888) ──> nb-<id>         JupyterLab（ユーザーごとに 1 コンテナ）
ノートブック ──> ゲートウェイの中継 ──> Fione      fione-sdk の呼び出し（公開しない）
Fione ──> ランチャー ──> Docker                  コンテナの起動と削除
```

- **ゲートウェイ**（`notebook-gateway`、nginx）は、JupyterLab を独自のオリジン（`127.0.0.1` のポート 8888）で公開し、ノートブックからの API 呼び出しを Fione へ中継します。ノートブックから Fione へ届く経路はこの中継だけで、中継は `/api/v1/auth`、`/api/v1/tokens`、`/api/v1/users` を拒否します。
- **ランチャー**（`notebook-launcher`）は、固定の仕様でユーザーごとのコンテナを起動します。Fione 自身は Docker ソケットに触れません。
- **ノートブックのコンテナ**は、Compose のネットワーク `notebooks`（内部ネットワーク）に置かれ、インターネットにも Fione の他のサービスにも届きません。

### 同一サイトのルール

Fione は自分の画面の中に JupyterLab を埋め込み、一度だけ使える起動リンクでブラウザをログインさせます。JupyterLab は、**同一サイト**のページからで、`Referer` が Fione のオリジン（`FIONE_PUBLIC_URL`。ノートブック画面が送ります）であるログインだけを受け付けます。そのため、2 つのオリジンは別のものにしつつ、同じサイトに置きます。

- **ローカル：** 同じホスト名で別のポートにします。たとえば `http://127.0.0.1:8080` と `http://127.0.0.1:8888` です。`localhost` と `127.0.0.1` は別のサイトです。Fione を `http://localhost:8080` で開くなら、2 つの URL にも `localhost` と書き、ブラウザでも同じアドレスを使ってください。
- **本番（HTTPS）：** 1 つの登録可能ドメインのサブドメインにします。たとえば Fione を `https://fione.example.com`、ゲートウェイを `https://nb.fione.example.com` にします。どちらも `https` にしてください。Fione とゲートウェイ以外に使わない登録可能ドメインをおすすめします（会社の `example.com` ではなく `fione-example.com` など）。

サイトが境界です。同じ登録可能ドメインのすべてのオリジン（`blog.example.com`、Wiki、プレビュー環境など）と、ローカルでは同じホスト名のすべてのポートが、ゲートウェイと同一サイトになります。`Referer` の確認により、そうしたページからブラウザを誰かのノートブックにログインさせることはできませんが、全ユーザーの JupyterLab は 1 つのゲートウェイのオリジンから配信され、信頼済みのノートブックの出力（ユーザー自身が書いた内容）はそこでサンドボックスなしに動きます（[既知の制限](known-limitations.md#notebooks)、英語）。

`FIONE_PUBLIC_URL` は、ブラウザから見た Fione 自身のオリジンです。TLS を終端するプロキシの後ろでは Fione がスキームを判断できないため、`https` のオリジンを指定します。ノートブックは、このオリジンからの埋め込みだけを許可します。`FIONE_NOTEBOOK_URL` はゲートウェイのオリジンです。どちらもパスは付けず、同じオリジンにはできません。

ゲートウェイをリバースプロキシの後ろに置くときは、ゲートウェイのポート 8888（既定では `127.0.0.1`）をノートブック用のホスト名で公開し、プロキシで `Host` ヘッダーを保ち、WebSocket のアップグレードを許可し（カーネルが使います）、通信がしばらくなくても早く切らないようにしてください。

## 権限を与える

管理者は常にノートブックを使えます。それ以外のユーザーには権限が必要です。

1. 管理者でログインし、「**ユーザー**」画面を開きます。
2. 「**ノートブック**」列で、そのユーザーに対して「**許可する**」を選びます（取り消しは「**取り消す**」）。

変更はすぐに反映されます。権限の取り消し、パスワードの再設定、権限を失うロールの変更を行うと、そのユーザーのノートブックは停止し、API トークンも無効になります。権限のないユーザーには「**ノートブック**」のリンクが出ず、画面は 403 を返します。

権限を与えた**閲覧者**もコードを実行できますが、トークンは読み取り専用です。ノートブックの権限は、多くてもユーザーのロールまでです。

## ノートブックを使う

1. ナビゲーションの「**ノートブック**」を開き、「**ノートブックを起動**」を押します。通常は 1 分かからずに起動します。画面に進み具合が出て、準備ができると JupyterLab が開きます。
2. ノートブックを作り（**File > New > Notebook**、カーネルは Python 3）、`fione-sdk` を使います。

```python
from fione_sdk import Client

fione = Client()                      # FIONE_URL と FIONE_TOKEN は設定済み
print(fione.projects())               # 見えるプロジェクト
```

ノートブックのトークンは、そのノートブックのために作られます。権限はユーザーのロールと同じです（管理者のノートブックは**編集者**として動きます）。ノートブックと一緒に期限切れになり、アカウント、トークン、Python モジュール、モデルのインポート、プロジェクトの共有は操作できません。それ以外の SDK の機能は使えます。データセット（`upload`、`read`、`preview`、`profile`）、`train`、`leaderboard`、`models`、`predict`、`run_module`（既存のモジュールを実行します。アップロードにはフルのトークンが必要です）などです。一通りの使い方は [SDK の README](../sdk/README.md)（英語）を参照してください。

新しいノートブックで最初の Shift+Enter が無視されたら、もう一度セルを実行してください。標準の JupyterLab でも起こります。

JupyterLab のターミナルを使えるのは管理者だけです。

### 画面の外から SDK を使う

`fione-sdk` は、自分の Jupyter やスクリプトからも使えます。インストールして、Fione のアドレスと API トークン（「**アカウント**」画面で作ります）を渡してください。

```sh
pip install ./sdk
export FIONE_URL=http://127.0.0.1:8080
export FIONE_TOKEN=fione_...
```

`Client()` は両方を環境変数から読みます。`Client(url=..., token=...)` のように引数でも渡せます。アカウント画面で作ったトークンは、ユーザーのロールの権限をそのまま持ち、無効にしない限り期限切れになりません。

## 制限

ノートブックのコンテナごとの上限：

| | |
|---|---|
| CPU | 2 |
| メモリ | 4 GiB（スワップなし） |
| プロセス数 | 512 |
| ケーパビリティ | なし。`no-new-privileges` |
| ネットワーク | 内部のみ。インターネットには出られず、Fione へは中継経由だけ |
| ファイル | ユーザー専用のボリューム |

- **同時に動くノートブック**は、全ユーザーの合計で `FIONE_NOTEBOOK_MAX_RUNNING`（既定 4）までです。超えると「起動中のノートブックが多すぎます」と表示されます。1 つで 2 CPU・4 GiB まで使えるので、許す数に合わせてホストを用意してください。
- **自動停止：** 30 分使われていないカーネルは停止します（5 分ごとに確認）。実行中のカーネルがなく、1 時間操作がないノートブックは終了し、コンテナも削除されます。
- **寿命：** ノートブックは、動いていても `FIONE_NOTEBOOK_MAX_LIFETIME_SECS`（既定 12 時間）で終わります。API トークンも一緒に終わります。もう一度画面から起動してください。
- **外部通信なし：** コードは何もダウンロードできないため、`pip install` は使えません。使えるライブラリはイメージのもの（JupyterLab、pandas、pyarrow、scikit-learn、matplotlib、httpx、`fione-sdk`）だけです。

## ファイルと永続化

ユーザーごとに名前付きボリューム `<project>-nb-home-<ユーザー ID>`（Compose のプロジェクト名は `fione`）があり、ノートブックの作業ディレクトリにマウントされます。ノートブックの停止、自動停止、寿命が来ても、ボリュームは残ります。**実行中のカーネルは残りません。** ノートブックを止めたときと、ランチャーを再起動したときに失われます。保存したノートブックとファイルは残りますが、ノートブックの信頼の署名はメモリにだけあるため、再起動後は、保存済みのノートブックの出力が「信頼されていない」と表示され、セルを実行し直すと戻ります。

JupyterLab の設定とレイアウトは保存されません。ゲートウェイが設定とワークスペースの書き込みを拒否するため、変えたテーマやパネルの配置は残りません。

`docker compose ... down` はランチャーを止め、ランチャーは停止時（と起動時）に、このプロジェクトのノートブックのコンテナを削除します。ボリュームは `down -v` でも残ります（ボリュームを作るのは Compose ではなくランチャーのため）。削除するには、ラベルで一覧にしてから消します。

```sh
docker volume ls -q --filter label=fione.project=fione
docker volume rm $(docker volume ls -q --filter label=fione.project=fione)
```

特定のユーザーのボリュームだけにするには `--filter label=fione.uid=<ユーザー ID>` を足します。動いているノートブックが使っているボリュームは削除できないので、先にノートブックを止めてください。

ボリュームは `down -v` でも残ります。`down -v` は Fione のデータベースを初期化してユーザー ID も最初からにするため、新しいユーザー 2 に以前のユーザー 2 のファイルが見えてしまいます。`down -v` の後（や `fione-data` を作り直したとき）は、ユーザーを作る前に上のコマンドでノートブックのボリュームを削除してください。

Fione でユーザーを削除すると、そのユーザーのノートブックとボリュームも削除されます。そのときランチャーに届かなかった場合はボリュームが残ります。Fione はユーザー ID を再利用するため、同じ ID の後のユーザーに前のファイルが見えてしまいます。ユーザーをもう作る前に、上のコマンドで削除してください。

## 停止

画面の「**ノートブックを停止**」は、コンテナを削除し、ノートブックの API トークンを無効にします。ファイルは残ります。JupyterLab を開いたまま停止すると、停止で切れたリクエストのエラー（502、「Failed to fetch」など）がブラウザのコンソールに出ることがありますが、問題ありません。

ノートブックが守らないものと、ノートブックのオリジンを共有している件の未決事項は、[既知の制限](known-limitations.md#notebooks)（英語）を参照してください。
